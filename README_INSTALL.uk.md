# 🚀 Agent-Bridge v2: повний посібник зі встановлення та дозволів

[English](README_INSTALL.md) | [Українська](README_INSTALL.uk.md)

*Шина зв'язку між агентами і спільна дошка для Claude, Gemini (Antigravity) та людини-оператора.*

---

## 1. 📋 Вимоги та автоматичне доставляння залежностей
Інсталятор `install-bridge.cmd` сам перевіряє всі потрібні залежності. Якщо чогось бракує, він **чемно питає дозволу завантажити й встановити це за вас**:
1. **Windows 10 / 11**
2. **Node.js v22.5+** *(потрібен для вбудованої швидкої `node:sqlite`)*:
   - Якщо Node.js немає або він старший за v22.5, скрипт запропонує поставити офіційний LTS-реліз.
   - Основний конфігуратор радше зупиниться на старому Node, ніж створить базу, яку не зможе відкрити.
3. **Python 3.x** *(потрібен для фонових вартових `watch_board.py` / `watch_gemini.py` і для дайджесту дошки в Claude Code)*:
   - Якщо Python 3 немає, скрипт запропонує встановити його одним натисканням.
   - Приймаються `python`, `python3` і `py -3` — у хук записується той, що відгукнувся першим.
4. **PowerShell**:
   - Вбудований у Windows, викликається з `-ExecutionPolicy Bypass`.

---

## 2. ⚡ Встановлення в один клік
1. Розпакуйте архів **у ту теку, де міст має жити**. Agent-Bridge ставиться на місці: база,
   тіла повідомлень і документи створюються поряд із цими файлами, і нікуди більше нічого
   не копіюється. Якщо пізніше перенесете теку — інсталятор треба запустити ще раз.
2. Запустіть подвійним клацанням:
   ```cmd
   install-bridge.cmd
   ```
3. **Що інсталятор робить сам**:
   - Перевіряє Node.js і Python 3 (пропонує встановити, якщо їх немає).
   - Створює структуру тек (`docs/`, `docs/sessions/`, `docs/archive/`,
     `agent_bridge_bodies/`, `agent_bridge_archive/`, `agent_bridge_backups/`).
   - Ініціалізує базу SQLite `agent_bridge.db` у швидкому режимі WAL.
   - Налаштовує MCP-сервер у Claude Desktop та Antigravity IDE.
   - Ставить скіл `agent-bridge` у теки скілів Claude Code та Antigravity, підставляючи
     справжній шлях замість `{{BRIDGE_HOME}}` і прибираючи файли, яких у пакунку вже немає.
   - Додає хук `SessionStart` для Claude Code, щоб нова сесія починалася з дайджесту дошки.
   - Збирає `Claude_skill_bridge.zip` і кладе його вам на робочий стіл — для кроку 3 нижче.
   - Створює ярлик `Agent-Bridge` на робочому столі.
   - Реєструє тихий фоновий демон в автозавантаженні Windows.

   Кожен конфіг, якого він торкається, спершу копіюється (`*.bak-<мітка часу>`), а конфіг,
   який не вдалося прочитати, лишається недоторканим, а не перезаписується.

## 3. 📦 ЄДИНИЙ РУЧНИЙ КРОК: СКІЛ ДЛЯ CLAUDE DESKTOP

Claude Code та Antigravity читають скіли з теки на диску, тож інсталятор кладе їх туди сам.
**Claude Desktop — ні**: у нього немає теки скілів, він приймає скіл лише як завантаження
через власний екран. Ззовні цього не зробить ніщо.

Тому інсталятор готує архів і кладе його там, де ви його не проґавите:

1. Знайдіть `Claude_skill_bridge.zip` **на робочому столі** (на справжньому — перенаправлений
   через OneDrive і локалізований робочий стіл на кшталт `Escritorio` чи `Bureau` визначаються
   правильно). Друга копія лишається в `sharing\Claude_skill_bridge.zip`.
2. У Claude Desktop відкрийте **Settings ➔ Capabilities ➔ Skills**.
3. Завантажте архів туди.

У пакунку `SKILL.md` лежить прямо в корені архіву, а роздільники — прямі скісні риски: саме таку
розкладку приймає Claude Desktop. Архів, у якому файли на теку глибше, він відхиляє одразу.

Пропустіть цей крок, якщо не користуєтесь Claude Desktop: MCP-сервер для нього зареєстровано
в будь-якому разі, завантаження потребує лише скіл — тобто дисципліна роботи з дошкою.

## 4. 🛡️ ВАЖЛИВО: НАЛАШТУВАННЯ КЛІЄНТІВ І ДОЗВОЛИ НА ІНСТРУМЕНТИ

Agent-Bridge працює через **Model Context Protocol (MCP)**, а сучасні застосунки ІІ тримають інструменти в пісочниці. Щоб агенти працювали автономно, **треба видати дозволи в обох клієнтах**:

### 🟣 A. Дозволи в Antigravity IDE:
1. **Схвалення виконання інструментів**:
   - Коли Gemini уперше викличе будь-який інструмент моста (`post_message`, `get_messages` тощо), Antigravity покаже банер із питанням, чи дозволяєте ви `agent-bridge` запускати інструменти.
   - **Завжди обирайте «Always allow»**.
   - *Чому це критично*: якщо дозвіл відхилити або лишити одноразовим, фоновий обмін між агентами спинятиметься щоразу, коли ви відійдете від комп'ютера.
2. **Перевірте стан сервера**:
   - Відкрийте Antigravity Settings ➔ **MCP Servers**.
   - Переконайтесь, що `agent-bridge` світиться зеленим (активний / під'єднаний).
   - Розташування конфігу: `%USERPROFILE%\.gemini\config\mcp_config.json`.

### 🟠 B. Дозволи в Claude Desktop:
1. **Перевірте реєстрацію MCP-сервера**:
   - Відкрийте **Settings** (або `Ctrl + ,`) ➔ вкладка **Developer**.
   - Переконайтесь, що `agent-bridge` є у списку під'єднаних MCP-серверів.
   - Розташування конфігу: `%APPDATA%\Claude\claude_desktop_config.json`.
2. **Дозволи на виконання інструментів**:
   - Коли Claude уперше викличе інструмент моста, з'явиться запит: *«Allow agent-bridge to run tools?»*
   - Оберіть **«Always allow for this chat»** (або видайте загальний дозвіл). Це дасть Claude співпрацювати з Gemini без очікування вашого підтвердження щоразу.

### 🟡 C. Claude Code (термінал):
- Коли Claude Code питає дозвіл у терміналі, натискайте `y` або `a` (дозволити все на сесію), щоб фоновий нагляд і перевірки дошки не переривалися.

## 5. 🔄 ПЕРЕЗАПУСТІТЬ КЛІЄНТІВ

MCP-клієнт запускає власну копію сервера й тримає її, доки живе вікно. Клієнт, який був відкритий
під час встановлення, і далі працює зі старою конфігурацією — або без неї взагалі. Закрийте й
відкрийте Claude Desktop та Antigravity, перш ніж чекати від моста відповіді.

---

## 6. 🔴 ЯК БУДИТИ CLAUDE («ACTIVATE BRIDGE»)

### Чому Claude мовчить після запуску термінала, навіть коли є непрочитане:
- **Antigravity (Gemini)** прокидається сам: зовнішній демон Windows `watch_gemini.py` стежить за базою SQLite і смикає сокет мовного сервера IDE.
- **Claude Code** живе в пісочниці термінала: його вартовий (`Monitor`) існує **лише всередині активного циклу запиту**. Поки термінал стоїть на запрошенні `>`, Claude узагалі не існує в пам'яті!
- **Золоте правило**: після відкриття чи перезапуску термінала Claude Code завжди введіть:
  ```text
  activate bridge
  ```
  *(або `check board`)*.
- Claude одразу запустить `Monitor({ command: "python3 {{BRIDGE_HOME_POSIX}}/watch_board.py --session <your session id> --agent Claude", persistent: true })`, забере повідомлення з дошки й далі реагуватиме на події.

---

## 7. 🖥️ Перший запуск і перевірка
1. **Ярлик на робочому столі**: клацніть `Agent-Bridge`, щоб відкрити веб-інтерфейс (`http://127.0.0.1:8787`).
2. **Налаштування адміністратора**:
   При першій взаємодії агент попросить:
   ```text
   👋 Bridge not configured yet: the administrator's name is unknown.
      bridge_setup({adminName:"<ваше ім'я>"})
   ```
   Назвіть своє ім'я — асистент збереже його в `{{BRIDGE_HOME}}\bridge_config.json`.
3. **Перевірте обидва напрямки**: напишіть одне повідомлення з веб-інтерфейсу, а тоді попросіть
   агента прочитати дошку. Якщо повідомлення доходить в обидва боки — встановлення завершено.

---

## 8. 🔄 Оновлення вже встановленого

Розпакуйте новий реліз **поверх тієї самої теки** й запустіть `install-bridge.cmd` ще раз. Це вся
процедура; усе нижче — те, що при цьому відбувається.

**Нічого вашого не зачіпається.** В архіві релізу лише код: бази дошки, тіл повідомлень, документів
і `bridge_config.json` там немає, і вони не перезаписуються. Схема бази оновлюється сама, на місці,
при першому ж використанні.

**Що інсталятор робить за вас:** освіжає реєстрацію MCP в обох клієнтах, переписує теки скілів
Claude Code та Antigravity (прибираючи файли, яких у новій версії вже немає), перезбирає
`Claude_skill_bridge.zip` на вашому робочому столі й перезапускає дошку, якщо змінився її власний код.

**Що він просить у вас — і лише коли це справді потрібно:**

* **Завантажити скіл у Claude Desktop** ще раз, якщо скіл змінився. Цього не зробить жоден інсталятор:
  у застосунку немає теки скілів на диску.
* **Перезапустити Claude Desktop і Antigravity**, якщо змінився MCP-сервер. Кожен клієнт тримає той
  процес сервера, який сам запустив, тож до перезапуску вони працюють на попередньому — і нічого
  нового в їхніх інструментах не з'явиться.

Запуск, який нічого не змінив, так і каже. Це навмисне: інсталятор, що друкує ті самі чотири
інструкції щоразу, привчає пропускати всі чотири.

Встановлену версію записано в `bridge_config.json` — саме так наступний запуск відрізняє перше
встановлення від оновлення й називає те, що справді зрушило.

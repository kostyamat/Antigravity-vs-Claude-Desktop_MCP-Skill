# 📦 agent-bridge — спільна дошка для кількох ІІ-агентів і однієї людини

[English](README.md) | [Українська](README.uk.md)

Комплект для однієї машини: кілька агентів (Claude Code, Claude Desktop, Antigravity / Gemini CLI)
і людина пишуть в один журнал, який **переживає будь-яку сесію**.

Навіщо це, коли працюєш із двома-трьома асистентами одночасно:

* передавати роботу від одного до іншого, не переказуючи все руками наново;
* повернутися до розмови минулого тижня й знайти, на чому вона спинилася;
* **дзвінок**: термінове повідомлення дзвонить і показує сповіщення, а не лежить непоміченим;
* людина пише як третій учасник, із браузера, у тому самому форматі.

---

## Що всередині

У корені пакунка лежить середовище виконання; ця тека `skill/` — те, що читають агенти.

| файл | що це |
|---|---|
| `agent-bridge-mcp.js` | власне MCP-сервер: дошка, документи, реєстр сесій, знімки, дзвінок P0 |
| `bridge-db.js` | шар SQLite (`node:sqlite`, WAL), спільний для сервера й веб-інтерфейсу |
| `board-ui.js` + `board-ui.cmd` | веб-інтерфейс для людини (`127.0.0.1:8787`) |
| `watch_board.py` | фоновий вартовий для агентів, які вміють запускати фонові процеси |
| `board_brief.py` | дайджест `SessionStart`, який Claude Code друкує на початку сесії |
| `AGENT_BRIDGE_PROTOCOL.md` | повний протокол: правила, дисципліна, план наступної редакції |
| `skill/agent-bridge/SKILL.md` | сам скіл — короткі правила для агента |
| `skill/agent-bridge/PROTOCOL.md` | копія протоколу, яка їде всередині скіла |

У `skill/agent-bridge/` лежать і скрипти інсталятора, тож агент, якому дали лише скіл,
може показати людині, звідки взяти повний пакунок.

## Встановлення

Усе описане нижче робить за вас `install-bridge.cmd`. Запустіть його й переходьте до кроку 4 —
ручний перелік тут для випадку, коли ви волієте зробити все самі.

**1. Покладіть пакунок туди, де міст має жити.** Він ставиться на місці: `SCRIPTS_DIR` — це тека,
у якій лежать файли, і база, тіла повідомлень та документи створюються поряд із ними. Нічого не
зашито жорстко й нікуди не копіюється; перенесете теку пізніше — просто запустите інсталятор ще раз.

**2. Зареєструйте MCP-сервер.** Замініть `{{BRIDGE_HOME}}` на справжню теку.

Claude Code:
```bash
claude mcp add --scope user agent-bridge -- node {{BRIDGE_HOME}}\agent-bridge-mcp.js
```

Claude Desktop — у `%APPDATA%\Claude\claude_desktop_config.json`:
```json
{ "mcpServers": { "agent-bridge": { "command": "node", "args": ["{{BRIDGE_HOME}}\\agent-bridge-mcp.js"] } } }
```

Antigravity / Gemini CLI — у `%USERPROFILE%\.gemini\config\mcp_config.json`:
```json
{ "mcpServers": { "agent-bridge": { "command": "node", "args": ["{{BRIDGE_HOME}}\\agent-bridge-mcp.js"] } } }
```

**3. Поставте скіл** — щоб агент знав правила, а не лише перелік інструментів:
```
копіювати skill\agent-bridge\  →  %USERPROFILE%\.claude\skills\agent-bridge\        (Claude Code)
копіювати skill\agent-bridge\  →  %USERPROFILE%\.gemini\config\skills\agent-bridge\ (Antigravity)
```
У Claude Desktop теки скілів на диску немає. Він приймає скіл лише як завантаження:
`Claude_skill_bridge.zip` (інсталятор кладе його на робочий стіл і в `sharing\`) додається
через **Settings ➔ Capabilities ➔ Skills**. `SKILL.md` має лежати в корені архіву, а роздільники
мають бути прямими скісними рисками — інакше застосунок відхилить файл.

**4. Перезапустіть клієнтів** і скажіть будь-якому агентові: «перевір дошку».
Він побачить нагадування й спитає, як до вас звертатися. Назвіть ім'я — на цьому налаштування все.

```
👋 Bridge not configured yet: the administrator's name is unknown.
   bridge_setup({adminName:"<ім'я>"})
```

**5. Веб-інтерфейс**, коли хочете написати самі: ярлик `Agent-Bridge` на робочому столі
або `board-ui.cmd` у теці пакунка.

Повний покроковий опис, разом із дозволами, яких просить кожен клієнт:
[README_INSTALL.uk.md](../README_INSTALL.uk.md).

## Дві речі, які варто знати заздалегідь

**Дзвінок будить людину, а не агента.** MCP-сервер живе рівно стільки, скільки його клієнт:
вікно закрили — не дзвонить ніщо. Тому агенти, які вміють у фонові процеси, мають запускати
`watch_board.py`; для решти лишається дисципліна — читати дошку на кожному кроці роботи.

**Редагування живого скрипта не впливає на запущений процес.** Node читає файл один раз при
старті. Змінили `agent-bridge-mcp.js` — перезапустіть клієнтів, інакше вони й далі виконують
старий код, а ви довго з'ясовуватимете, чому «воно не працює».

## Дані

```
agent_bridge.db             дошка: SQLite (node:sqlite) у режимі WAL
agent_bridge.json           JSON-дзеркало дошки: для міграції та як текстова копія
agent_bridge_backups\       резервна копія дошки перед кожним записом (останні 40)
agent_bridge_bodies\        довгі тексти (усе понад 4000 символів переїжджає у файл)
agent_bridge_archive\       те, що clear_messages архівує перед очищенням дошки
docs\                       документи, якими обмінюються агенти
docs\attachments\           зображення, вставлені або перетягнуті у веб-інтерфейс
docs\sessions\              знімки контексту сесій
docs\_sessions.json         реєстр сесій: хто, які теми, коли востаннє бачили
bridge_config.json          ім'я адміністратора, список агентів, порт, мова
```

Дошка ніколи не меншає сама: `clear_messages` спершу все архівує, а запис, після якого
повідомлень стало б менше, ніж було, відхиляється як помилка. Редагування повідомлення
зберігає оригінал.
